# 记忆管理指南

## 搜索策略

### 关键词 vs 语义搜索

`memory_search` 的 `search` 参数支持两种模式：

| 模式   | 示例                          | 适用场景               |
| ------ | ----------------------------- | ---------------------- |
| 关键词 | `search="git commit chinese"` | 知道具体术语，精确匹配 |
| 语义   | `search="用户写代码的习惯"`   | 模糊回忆，找相关内容   |

**推荐**：优先语义搜索，描述你想找的内容。如果结果不精确，再用关键词缩小。

### 过滤技巧

| 过滤目标   | 参数        | 示例值                   |
| ---------- | ----------- | ------------------------ |
| 特定分类   | `category`  | `"preferences"`          |
| 特定 Agent | `agentId`   | `"codex"`                |
| 特定会话   | `sessionId` | `"session-abc123"`       |
| 最近一周   | `startTime` | `"2026-06-03T00:00:00Z"` |
| 最近 N 条  | `limit`     | `5`                      |
| 分页       | `offset`    | `10`                     |

### 典型搜索场景

**新对话开始**：获取用户偏好和上下文

```
memory_search(search="用户偏好 项目约定 编码习惯", limit=10)
```

**用户询问过去信息**："我之前让你记住的那个..."

```
memory_search(search="用户描述的具体内容", limit=5)
```

**检查重复**：添加新记忆前

```
memory_search(search="待添加的内容摘要", limit=5)
```

## 索引机制

### 异步流程

```
memory_add / memory_update
    ↓
返回 { taskId: 123, status: "pending" }
    ↓
memory_task_wait(taskId=123, timeout=30)
    ↓
返回 { taskId: 123, status: "completed" }
    ↓
memory_search（验证可检索）
```

### 超时处理

`memory_task_wait` 默认超时 60 秒。索引通常几秒内完成。若超时：

- 不要立即重试 `memory_add`
- 等待几秒后再次 `memory_task_wait`
- 若持续超时，报告给用户

## 最佳实践

### 记忆内容编写

```txt
✅ 好的记忆：
"用户偏好使用中文编写 Git 提交信息，遵循 AngularJS 风格（feat/fix/docs等）"
"datadata-skills 项目约定：Markdown 文件不自动换行"
"用户使用 VS Code 作为主力编辑器，已安装 GitLens 扩展"

❌ 差的记忆：
"用户的一些偏好：中文、VS Code、TypeScript、Angular 风格提交"（太多不相关事实混在一起）
"项目约定"（太模糊，没有实质内容）
```

### 分类体系建议

| category        | 用途                       |
| --------------- | -------------------------- |
| `preferences`   | 用户偏好和习惯             |
| `conventions`   | 项目规范和约定             |
| `project-notes` | 项目相关的知识和背景       |
| `contacts`      | 联系人信息                 |
| `learnings`     | 从过去对话中学到的经验教训 |

### 合并压缩策略

当多条记忆描述同一主题时，应合并为一条，消除碎片化。

#### 相似度判断

添加新记忆前，`memory_search` 返回结果中满足以下条件之一即视为"相似"：

| 条件                           | 示例                                             |
| ------------------------------ | ------------------------------------------------ |
| 同一 `category` 下语义高度重叠 | 两条都是 `preferences` 分类，都关于 Git 提交习惯 |
| 关键词高度重合                 | 都包含 "commit"、"中文"、"Angular"               |
| 同一实体/主题                  | 都关于同一个项目、同一个人、同一个工具           |

#### 合并决策矩阵

```
搜索已有记忆
    │
    ├─ 完全重复（>95% 相似）
    │   └─ 跳过添加，不做任何操作
    │
    ├─ 新信息是已有信息的子集
    │   └─ 跳过添加，已有记忆已覆盖
    │
    ├─ 新信息是已有信息的超集
    │   └─ memory_update 替换为更完整版本
    │
    ├─ 互补关系（同一主题不同方面）
    │   └─ 合并内容 → memory_update
    │
    └─ 不相关（<50% 相似）
        └─ memory_add 新增独立记忆
```

#### 合并格式规范

合并后的 `content` 应保持清晰可读：

```
# 推荐：分号分隔同级信息
"用户偏好：使用中文编写 commit；遵循 AngularJS 风格；使用表情符号丰富视觉效果"

# 推荐：编号列举多项
"datadata-skills 项目约定：(1) Markdown 不自动换行 (2) Python 只用 stdlib (3) 文档使用中文"

# 不推荐：自然段落堆砌
"用户喜欢中文 commit 然后他还会用表情符号而且他好像也用 VS Code..."（混乱无结构）
```

### 冲突合并策略

当用户提供的信息与已有记忆**矛盾**时，需要判断是修正还是补充。

#### 冲突识别

| 信号                     | 含义               | 行动                         |
| ------------------------ | ------------------ | ---------------------------- |
| 用户说"不对，应该是..."  | 明确纠正           | 冲突合并                     |
| 用户说"改一下..."        | 明确修改           | 冲突合并                     |
| 用户说"我现在用..."      | 偏好变更           | 冲突合并（暗示旧偏好已过时） |
| 同一事实性信息前后不一致 | 隐式冲突           | 冲突合并（保留历史）         |
| 不同上下文的不同选择     | 不是冲突，是并存的 | 合并压缩或新增独立记忆       |

#### metadata.history 规范

```json
{
  "history": [
    {
      "value": "旧版本的内容",
      "updatedAt": "2026-06-01T10:00:00Z",
      "reason": "用户更新了电话号码"
    }
  ]
}
```

| 字段        | 必填 | 说明                     |
| ----------- | ---- | ------------------------ |
| `value`     | ✅   | 被替换的旧 `content` 值  |
| `updatedAt` | ✅   | 变更时间（ISO 8601）     |
| `reason`    | ❌   | 变更原因（如有明确说明） |

#### 冲突合并示例

**场景 1：事实性信息变更**

```
已有记忆（id=42）："用户电话: 1111"
用户说："我电话其实是 2222"
→ memory_update(id=42, content="用户电话: 2222", metadata={
    "history": [{"value": "用户电话: 1111", "updatedAt": "2026-06-10T14:00:00Z", "reason": "用户更正"}]
  })
```

**场景 2：偏好变更**

```
已有记忆（id=15）："用户使用 VS Code 作为主力编辑器"
用户说："我现在改用 Fleet 了"
→ memory_update(id=15, content="用户使用 JetBrains Fleet 作为主力编辑器", metadata={
    "history": [{"value": "用户使用 VS Code 作为主力编辑器", "updatedAt": "2026-06-10T14:00:00Z", "reason": "偏好变更"}]
  })
```

**场景 3：不是冲突 — 并存**

```
已有记忆（id=8）："项目 A 使用 pnpm 作为包管理器"
用户说："项目 B 我用 yarn"
→ 不是冲突，新增独立记忆：memory_add(content="项目 B 使用 yarn 作为包管理器")
```

### 生命周期管理

1. **添加前搜索**：避免重复记忆，触发合并压缩或冲突合并判断
2. **相似即合并**：发现相似记忆自动合并压缩，减少碎片
3. **冲突留历史**：信息冲突时保留 `metadata.history`，不丢失旧信息
4. **定期清理**：过时记忆及时 `memory_delete`
5. **纠正而非追加**：用户纠正旧信息时，用 `memory_update` 而非 `memory_add`
6. **标记来源**：在 `metadata` 中记录信息来源（如会话 ID），便于追溯

### 与 session memory 配合

- **持久化记忆**（本 skill）：跨会话保留的用户事实
- **Session memory**（`/memories/session/`）：当前会话的临时工作状态

会话开始时从持久化记忆加载上下文，会话中的临时状态放 session memory。
